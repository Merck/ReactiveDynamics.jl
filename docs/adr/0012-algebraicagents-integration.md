# ADR 0012 — AlgebraicAgents integration: a reactive network as a hierarchy node, with wired external coupling

- Status: Proposed 2026-06-21. A `ReactionNetworkProblem` already IS an AlgebraicAgents (AA) `@aagent` and can be entangled as a node in a larger AA hierarchy, but it is mute and deaf there: it implements none of AA's read/coupling surface (`getobservable`/`observables`/`_getparameters`/`_setparameters!`), and its expression IR has no way to read an EXTERNAL agent's state from within a rate/guard/predicate. This ADR pins the integration surface in both directions: OUTBOUND (RD exposes its state to the hierarchy, so AA `wires` can carry RD outputs to siblings) and INBOUND (RD reads sibling/parent observables via declared input ports fed by AA wires, surfaced to the IR as a new closed `ExternalRef` leaf). Answers the maintainer's Workstream-E question: "a reactive network becoming a node within the AlgebraicAgents hierarchy, with the possibility to query the external hierarchy state from within reactive-network dynamics." Maintainer ruling 2026-06-21: inbound coupling is via **wires + `ExternalRef`** (declarative), not a registry escape hatch.
- Verification note: every AA `file:line` was read against `~/.julia/packages/AlgebraicAgents/ovDs5` and every RD `file:line` against `ref-agents` (Julia 1.12.5). The load-bearing facts: RD's engine implements `_step!`/`_reinit!`/`_projected_to` (`src/solvers.jl:642/619/675`) so it is already a steppable AA node; AA's `step!` coordinates heterogeneous clocks via the least-projected-time gate — an agent's `_step!` runs only when `_projected_to(a) == t`, the hierarchy-wide minimum (`interface.jl:183-197`, `_projected_to` recursion `:213-227`); `getobservable`/`observables`/`getparameters` default to an `@error`/`nothing` and RD overrides NONE of them (`interface.jl:299-313`; grep of `src/` shows RD uses only `getagent`/`entangle!`/`inners`); the AA wire-read helper is `retrieve_input_vars(a)` = `Dict(w.to_var_name => getobservable(w.from, w.from_var_name) for incoming wires)` (`wires.jl:26-35`); wires are created host-side by `add_wire!(sys; from, to, from_var_name, to_var_name)` (`wires.jl:54-73`); the pre-step hook `_prestep!(a, t)` is `prewalk`'d over the whole hierarchy in `step!`'s FIRST phase, before any `_step!` (`interface.jl:184`, default no-op `:250`).
- Relates to: ADR 0001 (RD is the native `@aagent` engine, single clock `state.t += dt` `solvers.jl:668`, `_projected_to` `:675`), ADR 0004 (a wired-in external read never mutates structure — it is read-only, index-safe), ADR 0005 (the closed eval-free `ExprNode` IR + `validate`; `ExternalRef` is a new closed leaf like `Ref`/`TimeRef`), ADR 0006 (`getobservable` on the `"structured"` container was left unimplemented in §E — this ADR implements the RD-level `getobservable` that subsumes it; the registry boundary is the rejected alternative for inbound coupling), ADR 0008 (`TokenAgg` aggregates are among the observables RD exports outbound), ADR 0009 (open SPECIES ports for token-flow composition — `ExternalRef` input ports are the analogous OBSERVABLE-level read ports; §11 composition and §13 coupling are the structural and signal halves of the same hierarchy story), ADR 0010 (a Rule guard/`ExprNode` may read an `ExternalRef`, so endogenous decisions can be driven by external signals), ADR 0011 (`Invoke` is the rejected general-code inbound path — kept available as an escape hatch, not the default). CONTRACT §2 (the single clock, now coordinated by AA across the hierarchy), §4 (D1/D4 — the external-read pin is what keeps coupling deterministic), §9.4 (`getobservable` surfaces token aggregates). Becomes CONTRACT §13.

## Context

The brief's Workstream E is "make RD interoperate with AlgebraicAgents." Concretely the maintainer wants a reactive network to sit as ONE node inside a larger AA model — beside, say, a macro-economic ODE agent, a market-demand agent, or another reactive network — and to let the network's own dynamics READ the rest of the hierarchy ("set the Phase-3 spend rate from the macro model's interest rate"; "gate an acquisition rule on a sibling market-sentiment agent").

What already works (verified): `ReactionNetworkProblem` is an `@aagent` (`state.jl:40`) implementing the three AA stepping hooks (`solvers.jl:642/619/675`), so `entangle!(parent, rd)` makes it a hierarchy node and `simulate(parent)` drives it. Crucially, AA coordinates HETEROGENEOUS CLOCKS for free: `step!` projects the whole hierarchy to the least projected time and calls each agent's `_step!` only when `_projected_to(a) == t` (`interface.jl:191-197`). RD's `_projected_to` returns `state.t` until the horizon (`solvers.jl:675-677`), so an RD net with `dt = 1` interleaves correctly with a sibling stepping at `dt = 0.1`; no new clock code is needed (this is the ADR 0001 single-clock contract, now read as ONE node's clock within AA's multi-clock coordinator).

What does NOT work (verified): RD overrides none of AA's coupling surface. `getobservable(rd, name)` falls through to AA's default `@error` (`interface.jl:299`), so nothing in the hierarchy can read an RD species/observable and **no AA wire can originate from an RD net**. `_getparameters`/`_setparameters!` are unimplemented, so the hierarchy can't read or set RD params. And inbound: the entire `ExprNode` IR (`Ref{species|param|obs}`, `TimeRef`, `TokenAgg`) is network-local — there is no leaf that reads an external agent. REVIEW.md flagged exactly this ("No AA getobservable/wire/parameter API yet — bidirectional-observable integration is unbuilt"), and ADR 0006 §E left `getobservable` on the structured container as an explicit TODO.

So the work splits cleanly into two directions with very different risk profiles.

## Decision

### (A) OUTBOUND — RD becomes a first-class readable hierarchy node

Implement AA's read surface on `ReactionNetworkProblem`, so any agent (or wire) in the hierarchy can read RD state:

- **`observables(rd)`** → the list of names RD exports: every species name (`acs[:,:specName]`), every named observable (§9.4, `state.observables`), and a configurable set of `TokenAgg` aggregates (ADR 0008 §9.4, e.g. `nactive(Project, phase==:Phase2)`). This subsumes the ADR 0006 §E `getobservable`-on-the-`"structured"`-container TODO and resolves MVP finding G (per-tick token KPIs were unreadable without `getobservable`).
- **`getobservable(rd, name)`** → the current value: a species count is `state.u[idx(name)]`; a named observable is its `.sampled` field (`state.jl:37`); a token aggregate is the §9.3 deterministic reduction over the ordered token snapshot. `getobservable(rd, i::Int)` indexes the same list. Reads are pure and RNG-free.
- **`_getparameters(rd)` / `_setparameters!(rd, d)`** → expose/patch `state.p` (the param dict), so the hierarchy can read RD params and a coupled controller can set them. `_setparameters!` writes are param-only (never structural), so they are ADR 0004 index-safe; structural change stays on the append-only mutation API.

With these, an AA wire `add_wire!(sys; from=rd, to=other, from_var_name="Phase3_count", to_var_name=…)` carries an RD output into a sibling — RD is now a source as well as a sink.

### (B) INBOUND — RD reads external state via declared input ports + the `ExternalRef` leaf

RD dynamics read the external hierarchy through a declarative, eval-free channel — NOT by walking the hierarchy in arbitrary code (that is the rejected/escape-hatch path, §D).

**1. Declared input ports (model-local).** The model document gains a top-level `inputs[]` array — the OBSERVABLE-level analogue of the ADR 0009 §11.1 open SPECIES ports:

```jsonc
"inputs": [ { "port": "ext_rate", "default": { "Const": 0.0 } },   // a named read port + fallback before first wire delivery
            { "port": "market_sentiment" } ]
```

A port is a NAME the network may read; it carries an optional `default` used before any wire has delivered a value. The wiring itself — which external agent feeds which port — is established HOST-SIDE at composition time via `add_wire!(sys; from=macro_model, to=rd, from_var_name="rate", to_var_name="ext_rate")` (`wires.jl:54-73`), exactly as the registry (ADR 0006 C) and the §11 host-side composition keep cross-hierarchy topology OUT of the inert RD document. The RD JSON stays self-contained: it declares the ports it consumes; it never names the foreign agents that fill them.

**2. The `ExternalRef{port}` ExprNode leaf.** A new closed leaf in the ADR 0005 IR family, a sibling of `Ref{obs}`:

```julia
struct ExternalRef <: ExprNode; port::Symbol end     # reads the latched value of a declared input port
```

It lowers (`to_expr`) to a read of the per-tick external-input buffer: `:(state.external_inputs[port])`. So a rate `phase3_spend * ExternalRef(ext_rate)`, a guard `ExternalRef(market_sentiment) < threshold` (ADR 0010), or a `TokenPredicate.value` (ADR 0008) can all read external signals through one uniform, validatable node. `validate` (CONTRACT §8.3) gains rule 8: every `ExternalRef.port` is a declared `inputs[]` port; an undeclared port is a diagnostic, never an eval. `ExternalRef` is eval-free and JSON-Schema-enumerable like every other leaf.

**3. The latch point — determinism (the load-bearing rule).** External inputs are read ONCE per tick and buffered, at a PINNED point: RD implements AA's `_prestep!(rd, t)` hook to call `retrieve_input_vars(rd)` (`wires.jl:26-35`, which does `getobservable(w.from, w.from_var_name)` over RD's incoming wires) and store the result into `state.external_inputs::Dict{Symbol,Any}`. This pin is what makes coupling deterministic, and it is forced by an AA fact: `step!` advances sibling agents in `values(inners(a))` order — i.e. raw `Dict` order (`interface.jl:185`) — so a LIVE cross-agent `getobservable` mid-`_step!` would see a sibling's pre- or post-step value depending on hash-iteration order, a CONTRACT §4 D4 violation. Reading at `_prestep!` instead — which `step!` `prewalk`s over the WHOLE hierarchy in its FIRST phase, before ANY agent's `_step!` runs that tick (`interface.jl:184`) — means RD always reads each source's value as projected to the PREVIOUS tick boundary, independent of sibling step order. This is explicit (Jacobi-style) co-simulation: a one-tick coupling lag, no algebraic loop, fully reproducible under `(hierarchy, seed)`. Within RD's own `_step!`, every `ExternalRef` read during `sample_transitions!`/`evolve!`/rule-firing returns the same buffered value, so a rate and a guard that read the same port in one tick agree (the same discipline §9.5 pins for `TokenAgg`).

`ExternalRef` is 𝓕ₜ-measurable: it reads past/current external state (the previous boundary's projection), never the future, and consumes no RNG — so it composes with the §4 determinism contract and the §9.5/§12 measurability rules without exception. `state.external_inputs` is transient run-state re-derived every `_prestep!`, so `reinit!` (§10.4) need only clear it and `dump_state` (§10.5) need not persist it (it is recomputed on the next prestep from the restored hierarchy).

### (C) Clock coordination is AA's, not RD's

When RD is a hierarchy node, the authoritative stepping driver is AA's `step!`/`simulate` on the ROOT, not `simulate(rd)` directly. RD's single-clock contract (§2.1, `state.t += dt`) is unchanged — it is now ONE node's local clock, and AA's least-projected-time gate (`interface.jl:191-197`) interleaves it with sibling clocks. Two consequences pinned: (1) `simulate(rd, max_t)` still works for a STANDALONE net (the §10.4 max-time/returns-agent gotcha), but a coupled net MUST be driven via the root; (2) RD's `dt` becomes its coupling granularity — finer `dt` reduces the one-tick external-read lag (§B3), the same `dt`-as-resolution guidance as §2.6.

### (D) Rejected / escape hatch: inbound coupling via the registry (`Invoke`)

The alternative inbound design — a host-registered function (ADR 0006 §C / ADR 0011 `Invoke`) that receives `state` and itself walks `getagent(state, "../sibling")` + `getobservable` — is REJECTED as the default: it is imperative host code, not declarative, not statically validatable, and re-introduces the trust-boundary obligations (ADR 0011 O1–O4) for what is fundamentally a read. It remains AVAILABLE as the escape hatch for reads that genuinely exceed a single wired port (a cross-hierarchy reduction over many agents, a glob/regex agent query `getagent(a, glob"**/market/")`, `paths.jl:80`), exactly as ADR 0011 positions `Invoke` relative to the declarative verbs. `validate` steers authors to `ExternalRef`+wires; `Invoke` carries the O1–O4 host obligations. This mirrors the ADR 0008/0011 "declarative node + escape hatch" pattern already adopted.

## Consequences

- RD is a first-class AA hierarchy node in BOTH directions: readable by the hierarchy (A) and able to read it (B), so a reactive network composes with ODE/ABM/other reactive agents under one `simulate(root)` with coordinated heterogeneous clocks (C).
- Inbound coupling is declarative, eval-free, and deterministic: one new closed `ExternalRef` leaf + a model-local `inputs[]` port list + a pinned `_prestep!` latch. No RCE surface is added (the JSON names a port, never foreign Julia; §8.4 S4 holds), and the §4 D1/D4 determinism contract extends to coupled runs by the latch rule.
- The integration completes two earlier TODOs: ADR 0006 §E (`getobservable` on the structured container) and MVP finding G (per-tick token KPIs), both subsumed by the RD-level `getobservable` (A).
- Wires give the BD demo a clean macro-coupling story: a sibling macro/market agent feeds `interest_rate`/`sentiment` into RD ports that drive spend rates and the acquisition rule (ADR 0010) — the lever can now be state-contingent on EXTERNAL state, not just internal portfolio state.
- Costs: implement `getobservable`/`observables`/`_getparameters`/`_setparameters!` on `ReactionNetworkProblem` (A, mechanical); add the `inputs[]` model array + `ExternalRef` leaf + `to_expr` lowering + `validate` rule 8 (B); add the `state.external_inputs` buffer field and the `_prestep!(rd,t)` override that fills it (B3); wire `reinit!` to clear the buffer (D7). One real semantic commitment — the one-tick explicit-coupling lag (B3) — which an implicit/fixed-point coupling would remove at the cost of an intra-tick solve; that is explicitly OUT of scope.

## North-star tie-in (BD)

The pharma pipeline RD net becomes a child of a portfolio-level AA model that also holds a macro agent (rates, FX) and a market agent (competitor launches, demand). The macro agent's `discount_rate` wires into an RD `ext_rate` port; the Phase-3 spend rate and the rNPV valuation read `ExternalRef(ext_rate)`. The acquisition Rule (ADR 0010) guards on `ExternalRef(market_sentiment) > θ && portfolio_proxy < acq_trigger` — an endogenous decision driven by BOTH internal portfolio state and external market state. Conversely the RD net exports `nactive(Project, phase==:Phase3)` and portfolio valuation outbound (A), which a downstream reporting/finance agent reads via wires. The whole coupled model runs under one `simulate(root; seed)`, reproducible by the §B3 latch.

## Invariants

1. **RD is a readable node.** `getobservable(rd, name)`/`observables(rd)` resolve for every exported species/observable/aggregate; an unknown name is a diagnostic, never AA's silent `@error` fall-through.
2. **Inbound reads are 𝓕ₜ-measurable and pinned.** Every `ExternalRef` read in a tick returns the value latched at `_prestep!` (the source's previous-boundary projection), identical across all read sites in that tick, independent of AA sibling step order (§4 D4) — no live mid-step cross-agent read.
3. **Explicit coupling, no algebraic loop.** Coupling carries a one-tick lag (Jacobi); RD never solves a fixed point against external state within a tick. `(hierarchy, seed)` fully determines the coupled trajectory (§4 D1).
4. **Eval-free coupling.** `inputs[]`/`ExternalRef` reference ports by name; the foreign-agent topology lives in host `add_wire!` calls, never in the RD document; no file bytes are parsed/eval'd (§8.4 S4).
5. **Read-only inbound, param-safe outbound.** An `ExternalRef` only reads; `_setparameters!` writes params only (ADR 0004 index-safe). Neither path reindexes or mutates structure; structural change stays on the append-only API.
6. **Clock subordination.** A coupled RD net is driven by `simulate(root)`; its single clock (§2.1) is coordinated by AA's least-projected-time gate, and its `dt` is the coupling granularity.

## Open questions

- **Outbound observable set for token aggregates.** `observables(rd)` should list species + named observables trivially; for `TokenAgg` aggregates, decide whether they are auto-enumerated (every registered `nactive`/`sumattr` over each structured kind × declared phase value — potentially large) or explicitly declared as named observables. Lean explicit (an author lists the aggregates worth exporting), mirroring the ADR 0008 `getobservable`-on-container note.
- **`getobservable` observation point for token aggregates.** A sibling reading `getobservable(rd, "nactive_Phase2")` mid-hierarchy-step sees RD's `state.u`-consistent counts as of RD's last completed `_step!` (since cross-agent reads are pinned at `_prestep!`, §B3). Confirm this matches the §9.5 pre-`evolve!` internal observation point closely enough that an external reader and an internal `TokenAgg` agree to within the one-tick coupling lag; document the lag explicitly.
- **`_setparameters!` and frozen TVEs.** Setting a param mid-run is index-safe, but a param feeding an attribute frozen at spawn (§5 A3 / MVP finding D-bis: `cycletime`/`prob_of_success` read from the spawn snapshot) only affects instances spawned AFTER the set — the same mid-run-TVE caveat as the synergy levers. Note it where `_setparameters!` is documented.
- **Standalone vs coupled `reinit!`.** `reinit!` on a coupled hierarchy is AA's `reinit!` (prewalk, `interface.jl:257-265`); confirm RD's `_reinit!` (§10.4, restoring marking/RNG/counters) composes correctly when invoked as part of a hierarchy-wide reinit, and that the external-input buffer is cleared (not stale) on the first post-reinit `_prestep!`.
- **Implicit/fixed-point coupling.** Out of scope here (explicit/Jacobi only). If a tight feedback loop later needs a within-tick fixed point (algebraic coupling), that is an AA-level `Opera` interaction (`opera.jl`) design, a separate ADR.
