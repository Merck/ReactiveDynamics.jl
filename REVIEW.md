## What this package is

ReactiveDynamics.jl (v0.2.7) is a domain-specific modeling framework for "reaction (transportation) network"-type problems, built on **Catlab attributed C-sets (ACSets)** and emitting a **SciML `DiscreteProblem`**. The intended domain is **system-dynamics-style modeling of business / R&D processes** (budgeting, ledger, what-if scenarios), not chemistry — chemical reaction networks are just the archetype. It is part of Merck's **DyVE** (Dynamics of Value Evolution) family alongside [AlgebraicAgents.jl](https://github.com/Merck/AlgebraicAgents.jl), CEEDesigns.jl, and GeneratedExpressions.jl.

The central abstraction is a **transition**: a *stateful* (acts over a cycle time), Poisson-rate-spawned stochastic rule that transforms **resources** (species) via generalized stoichiometry. Transitions carry attributes (priority, probability-of-success, capacity, cycle time, max lifetime, post-action). Resources carry a **modality** (`:nonblock`, `:conserved`, `:rate`) governing allocation semantics, plus a cost/reward/valuation **ledger**. The package also has events/callbacks, observables, model unions/joins, TOML/CSV/JLD2 serialization, and NLopt-based optimization/fitting — all driven by a macro-based modeling metalanguage plus a GeneratedExpressions.jl comprehension layer.

## Strategic goals (why we are revisiting it)

1. **Refine the simulation backbone / model / ontology** for correctness, expressivity, clarity, organization.
2. **Catch bugs, inconsistencies, dead code, silent failures, macro misuse.**
3. **Make it production-ready** for practitioners modeling business processes (budgeting, ledger, what-if).
4. **Make it ready for agentic development of models** — typed description schemas, declarative specs, a non-macro builder API.

One-line state of the code: *a genuinely interesting domain abstraction that currently works as a tutorial demo but is not production-ready and is hostile to agentic authoring* — several headline features (model `@join`, the `:nonblock` modality, finite `transCapacity`, range-less observables, the optimizer's uninitialized-param path) crash or silently return degenerate results on their first real use, and model import is an arbitrary-code-execution surface.

### Data flow

`@ReactionNetwork` (macro) → `get_data` parses the block into `(transitions, reactants, obs, events)` → `merge_acs!` populates the **`ReactionNetwork` ACSet** (the persistent model) → `@prob_*` macros mutate attributes → `DiscreteProblem(acs)` runs `remove_choose` + `compile_attrs` (which **`eval`s** each expression attribute into a closure) and builds a **`ReactiveDynamicsState`** carried in `prob.p[:__state__]` → SciML solves with a `FunctionMap`, the step closure `f` calling `free_blocked_species!`/`update_observables`/`sample_transitions!`/`evolve!`/`finish!`/`event_action!` each step and appending to `state.log` → `@plot` reads species trajectories or the structured log; `@optimize`/`@fit` wrap the solve in an NLopt objective.

The model lives in **two representations**: the static `ReactionNetwork` ACSet (authoring/serialization) and the compiled `ReactiveDynamicsState` (execution). Expression-valued attributes are the seam between them and the source of most complexity.

## Code conventions & gotchas (read before editing)

- **ACSet access**: `acs[i, :attrName]` reads, `acs[i, :attrName] = v` / `set_subpart!(acs, i, :attrName, v)` writes; `nparts(acs, :S)` counts; `incident(acs, val, :attrName)` finds parts; `subpart(acs, :attrName)` is the raw column. Attribute symbols **must be quoted** (`:specModality`, not `specModality` — the latter is an unbound identifier and the cause of bug #4).
- **Two clocks**: `ReactiveDynamicsState.t` (the authoritative model clock, manually `+= tstep` in the step closure) vs the SciML integrator's `t`. The physics reads `state.solverargs[:tstep]`, not the integrator `dt`. `remake` currently forces them equal but nothing enforces the invariant (design-smell #19; also the chief risk for AlgebraicAgents integration).
- **Expressions are compiled by `eval`**: `wrap_expr` (`compilers.jl:117`) `eval`s a fresh closure; `context_eval` then uses `Base.invokelatest` to dodge world-age. This is **per-reactant, per-step** for expression-valued stoichiometry (bug #3) — not thread-safe, blocks `EnsembleThreads`. Do not add more runtime `eval`; prefer compile-once / `RuntimeGeneratedFunctions.jl`.
- **`eval` on deserialization**: `convert(::Set{Symbol}, ::String)`, `convert(::FoldedObservable, ::String)`, and `load_network` all `eval` strings from the model file in module scope. **Importing an untrusted `.toml`/`.csv` is RCE** (security #2). Treat import as a trust boundary.
- **Sentinels are inconsistent**: `defargs` defaults `prmVal`/`metaVal` to `missing`, but consumers filter on `isnothing` (which is `false` for `missing`) — `missing` leaks into params, and the `metaVal` default is a *latent crash* because `Missing ∉ SampleableValues` (#18). `optim.jl` uses `v === NaN` as "unset" (works for literal `Float64` NaN but fragile).
- **Macros vs functions**: the reaction DSL (`@ReactionNetwork`, arrows, `@choose`, `@register`) legitimately needs macros. The **configuration macros** (`@mode`, `@cost`/`@reward`/`@valuation`, `@prob_*`, `@aka`) do *no* metaprogramming — they only reshape `X = 1 Y = 2` surface syntax into a `Dict` and call an unexported `!`-function. Prefer adding/using the underlying functions; keep macros as thin sugar.
- **Pseudo-macros**: `@ct`/`@per_step`/`@choose`/`@conserved`/`@rate`/`@nonblock`/`@take` are **not** defined macros — they are recognized by `macroname(ex)` string comparison after the DSL body is quoted. Unknown `@foo` markers are silently swallowed, not rejected (#25).
- **Identity by name**: `merge_acs!`/`union_acs!`/`equalize!` all assume species/transition identity by name; there is no enforced uniqueness invariant.

## Confirmed defect catalog (prioritized)

Ranked by severity × blast radius. Each was adversarially verified against the source. Use this as the bug backlog; fix criticals/highs before any refactor.

### Critical
1. **`union_acs!`/`@join` is broken by an unconditional mid-loop `return (acs1, acs2)`** — `src/operators/joins.jl:17`. On the first species-loop iteration the function returns a 2-tuple; the modality union, species/transition/param/meta merges, and the real `return acs1` are all **dead code** (with leftover debug `println`s at 18–21). Every model join silently produces a degenerate ACSet with ~one species and zero transitions. obs (`:obs`) and event (`:E`) merging are not implemented at all. **Fix**: delete line 17 and the printlns; let the loop fall through; add obs/E merge; add a join regression test asserting merged counts + `ReactionNetwork` return.
2. **Model import is arbitrary code execution; export is lossy** — `src/loadsave.jl:62,68-70`; `src/ReactiveDynamics.jl:96-98`. `load_network` `eval`s `prmVal`, every `registered` body, and (via `convert`) every `specModality`/`obsOpts` string from the file, in module scope. Separately, `export_network` never emits `registered`, so `@register`'d helpers are silently dropped and re-import fails at solve time; TOML and CSV diverge for non-numeric attrs. `@export`/`@import` are exported but undefined. **Fix**: gate `eval` behind an opt-in `trusted` flag (default off), parse `Set{Symbol}`/`FoldedObservable` without `eval`, make `registered` symmetric (or drop it), one typed (de)serialization table for both formats, delete the phantom exports, add round-trip equality tests.
3. **Per-step `eval` of a fresh closure in the hot loop** — `src/compilers.jl:117`, invoked from `state.jl:215` (`sample_transitions!`) and `solvers.jl:251` (`finish!`). For expression-valued stoichiometry like `Poisson(0.3γ)X` this recompiles every timestep × reactant × trajectory — eval-bound, world-age-bumping, not thread-safe (the root cause of the `invokelatest` indirection). **Fix**: compile each unique expression **once** at problem-build time and store the closure in the recipe; prefer `RuntimeGeneratedFunctions.jl`.

### High
4. **`mode!`/`@mode` uses bare `specModality` not `:specModality`** — `src/interface/update.jl:106`. Unbound identifier → `UndefVarError` on any `@mode` call. **Fix**: quote both occurrences.
5. **`free_blocked_species!` references undefined `q`** — `src/solvers.jl:296`. The `:nonblock` resource-return path throws `UndefVarError` the first time an ongoing transition carries a `:nonblock` LHS token. The entire `:nonblock` modality is non-functional (latent only because no test/tutorial uses it). **Fix**: bind `trans.q * tok.stoich` mirroring the `:conserved` path; verify it matches what `get_reqs_ongoing!` reserved.
6. **`resample!` assigns nonexistent `Observable.val`** — `src/state.jl:154`. The struct field is `sampled`; a range-less observable (default) crashes on the first `update_observables`. **Fix**: `o.sampled = missing`.
7. **`add_to_spawn!` wrong-arity `findfirst` + mutates `transHash`** — `src/state.jl:270-273`, hit from `solvers.jl:145` when `transCapacity` < per-step demand. `findfirst(pred)` with no collection → `MethodError`; and it adds a number to a Symbol identity hash. Compounded by `state.jl:226` zeroing the whole `transToSpawn` vector inside the per-transition loop. Finite `transCapacity` is completely non-functional (default `Inf`, so untested). **Fix**: give `findfirst` the collection, increment `:transToSpawn`, move the reset out of the loop, add a backlog test.
8. **`prep_params!`/`prep_u0!` crash on the uninitialized-param warning path** — `src/optim.jl:169,179`. `any(p -> (p[2] === NaN) && @warn(...), …)` — `@warn` returns `nothing`, so the predicate yields `nothing` in boolean context → `TypeError`, exactly when a free var/param can't be initialized. Breaks `@optimize`/`@fit`/`@fit_and_plot`/`@build_solver`. **Fix**: explicit loop for the warning; fix the `prep_u0!` "prm" message; later replace the NaN sentinel with `missing`.
9. **Tutorials/README use silently-dropped attribute names** — `src/interface/create.jl:171-184`, `prettynames` at `ReactiveDynamics.jl:100-110`. `get_transitions!` `continue`s past any key not in `prettynames`; `cycle_time`/`probability_of_success` (used in `rd_example.jl`, `joins/submodel.jl`, README) are not aliases, so those settings are silently discarded and transitions run with defaults. `transMultiplier` has no alias at all. **Fix**: error/`@warn` on unconsumed attrs; add `:cycle_time`/`:probability_of_success`/`:multiplier` aliases; assert via test.
10. **Construction is eval-coupled and untyped (the Goal-4 blocker)** — `ReactiveDynamics.jl:11-12` (`SampleableValues = Union{Expr,Symbol,AbstractString,Float64,Int,Function}`), macro-only entry points, no whitelist, `forbidden_symbols`/`reserved_names` defined but unenforced. Rates, stoichiometry, probabilities, capacities, post-actions, event triggers are one untyped soup mixing data and code; a JSON-schema spec cannot represent `Expr`/`Function`. **Fix**: typed `ExprNode` IR + non-macro builder API + a `validate(acs)` pass (see agentic section).
11. **No RNG seeding / reproducibility** — `solvers.jl:223,265,444`, `state.jl:95,140,149`, `optim.jl`. All stochasticity draws from the global default RNG; `prob_func` ignores the trajectory index. Single runs and ensembles are not reproducible; parallel ensembles would be racy. **Fix**: thread an `rng::AbstractRNG` through state and every draw; `seed` kwarg; seed each trajectory from its index.
12. **Type-unstable, allocation-heavy state; `deepcopy` per trajectory and per loss sample** — `state.jl:32-50,101,243`, `solvers.jl:442`, `optim.jl:93`. `Dict{Symbol,Vector{Any}}`, `p::Any`, `contains(string(key),"trans")` string-routing per access, `as_state` `deepcopy`s the whole state at 100 points × trajectory. **Fix**: concretely type `p`; precompute a name→index `Dict` and per-attribute classification; reuse preallocated buffers; evaluate observables against `sol(t)` without full `deepcopy`; make `n_steps` a kwarg.
16. **Test suite is six assertion-free smoke tests** — `test/`. (See "Build / test" above.) **Fix**: add a real unit-test layer (parsing values, allocation/conservation/capacity invariants after one `evolve!`, join/equalize counts, optimize/fit improvement, serialization round-trip equality).

## Ontology assessment

**Verdict**: the core abstraction is genuinely good and distinctive and a strong fit for system-dynamics R&D/business modeling, but the ontology is **under-typed**, internally **inconsistent** in several load-bearing places, and currently undermined by the bugs above that make core operations (join, modality tagging, `:nonblock`, the ledger, events) silently non-functional. The C-set gives a clean structural skeleton, but the structure/numerics separation is only partial and the typing is **inert** (the six `AttrType`s are never used for dispatch or validation).

Three structural weaknesses:
1. **One catch-all attribute type.** Almost every behavioral attribute is `SampleableAttributeT` = `Union{Expr,Symbol,AbstractString,Float64,Int,Function}`. Rates, priorities, probabilities (should be `[0,1]`), capacities (`≥0`/`Inf`), cycle times (`≥0`), and effectful post-actions share one type with no invariants. This is the central limit for typed/agentic authoring.
2. **Non-orthogonal modalities** (bug #13): two genuinely orthogonal axes plus a flag, stored as an unvalidated `Set{Symbol}` with an undocumented cross-product the solver handles inconsistently.
3. **Structure is implicit, not morphic.** The transition↔reactant relation (which species a transition consumes/produces, with stoichiometry and modality) is parsed out of the `trans` `Expr` at runtime rather than encoded as ACSet morphisms — so there are no schema-enforced foreign keys, no structural validation, no graph rewriting.

**Proposed refined ontology** (concrete): keep `S`/`T`, but (a) split modality into typed orthogonal fields `allocation::AllocationMode`, `return_policy::ReturnPolicy`, `nonblock::Bool`, validated at construction; (b) replace the catch-all with distinct validate-on-assign types (`ProbabilityT∈[0,1]`, `RateT`, `CountT`, `NonNegT`, `ActionT` for effectful post-actions, distinct from sampled numerics); (c) **promote the reactant relation to a real morphic incidence object** `Reactant` with morphisms `reactant_trans: Reactant→T`, `reactant_species: Reactant→S` plus `stoich`/`side`/modality — making the model a real bipartite graph; (d) add first-class domain objects the business/R&D use-cases need: **Account/Role** (the natural home for the dead `@prob_role`/`@list_roles` exports), a precise double-entry-style **Ledger** (period cost/reward, net flow, cumulative cash, separate mark-to-market valuation, with units), explicit **Constraint** invariants (budget ≥ 0, headcount caps) as data, first-class **Scenario** override-sets for what-if branching, and a **Calendar/FiscalPeriod** business-time layer; (e) make the model a pure typed data artifact (store an `ExprNode` IR, no `Expr`/`Function`) so the whole ontology is serializable/validatable/round-trippable without `eval`, with compilation to closures a separate downstream stage; consolidate `defargs`/`prettynames`/`species_modalities` into one `const`, typed, documented metadata block.

**Fix the load-bearing bugs first** (#1 join, #4 mode, #5 nonblock, #14 ledger) — they make the advertised ontology silently non-functional, and tests for join/`@mode`/nonblock/ledger would have caught all of them.

## Macro-misuse catalog

The maintainer's concern is borne out: the macro layer is the weakest part. Prioritized:
1. **`eval` everywhere** (root liability): per-step eval in the hot loop (#3), eval-on-deserialize (#2), eval-into-module-scope `@register` (#15), eval-at-wrong-scope `@prob_meta`/`set_params!`/`set_valuation!` (#15). → compile-once via `RuntimeGeneratedFunctions.jl`; per-model env; restricted IR interpreter on load.
2. **Pseudo-macros that aren't macros** (#25): `@ct`/`@per_step`/`@choose`/`@conserved`/`@rate`/`@nonblock`/`@take` recognized by string only, no validation. → typed marker enum + allowlist.
3. **Macros that do no metaprogramming** (highest-leverage for Goal 4): `@mode`/`@cost`/`@reward`/`@valuation`/`@prob_*`/`@aka` just reshape surface syntax → a `Dict`. → plain functions over `Pair`/`NamedTuple`/`Dict` (the `!`-functions already exist, just unexported); keep macros as optional one-line sugar that escapes args.
4. **Copy-paste boilerplate** (#24): the same `dictcall`/`exs_`/`exs__`/`foreach` block in 5–6 macros; opaque eval-of-quote valuation factory; hand-poking `dictcall.args[2].args`. → one `parse_assignment_dict` + `apply!`.
5. **Hygiene leaks** (#20): `args_kwargs` escapes positional args but not kwarg RHS; `@solve`/`@problematize` splat un-escaped kwargs. → escape and partition.
6. **Dead/broken/phantom surface** (#17, #24): `get_reaction_line`, `normalize_pcs!` second branch, `@prob_init_from_vec`, and five exported-undefined macros + `check_params`. → delete or implement; make the export list authoritative with a test.

**Guiding principle**: the reaction-network DSL legitimately needs macros and should keep them; the configuration/mutation macros should become a typed function API. That split simultaneously removes the scope footguns, the boilerplate, and the agentic-hostility.

## Agentic-authoring design (Goal 4)

Make a model a **pure, typed, validatable, serializable data artifact** an agent can emit and the framework can check at the boundary — eliminating the `Expr`/`Function`/`eval` soup. Concretely:

- **Typed expression IR** — a closed sum type with **no** `Expr`/`Function` (trivially JSON/TOML-serializable + JSON-Schema-describable): `Const(value)`, `Ref(kind∈{species,param,obs}, name)`, `TimeRef` (the `@t()` builtin), `Call(op∈OP_WHITELIST, args)`, `Sample(dist∈DIST_WHITELIST, args)`, `Choose(options)`. A validation pass rejects any op/dist outside the whitelist with a structured, machine-readable error. The existing query primitives (`@t`, `@take`, `@periodic`, `set_params`) become named IR builtins.
- **Typed model spec** mirroring the refined ACSet, every former-`SampleableValues` field now a concrete scalar or an `ExprNode`: `ModalitySpec`, `ReactantSpec`, `SpeciesSpec`, `TransitionSpec`, `EventSpec`, `ObsSpec`, `ParamSpec`, `MetaSpec`, `AccountSpec`, `ScenarioSpec`, `RegisteredFn` (helpers as **IR**, not eval'd source), assembled into one `RNSpec`. This `RNSpec` is the canonical persisted agent-facing artifact.
- **Non-macro builder API** the agent calls (macros become sugar lowering to it): `add_species!`, `add_transition!`, `set_init!`, `set_param!`, `set_modality!`, `set_account!`, `build_model(spec)::ReactionNetwork`.
- **Validation + serialization**: `validate(spec)::Vector{Diagnostic}` before constructing anything (unknown names/ops/dists, illegal modality combos, out-of-range bounds, reserved-name collisions, dangling refs); serialize/deserialize via StructTypes/JSON3 against a published JSON Schema — lossless and **no `eval`**, closing the RCE and the TOML/CSV asymmetry at once. Legacy stringy TOML/CSV becomes an import-only shim that lowers into the IR with validation.
- **IR → ACSet + safe evaluation**: keep the ACSet as the execution substrate; compile validated `ExprNode`s once (interpreter over the whitelist, or `RuntimeGeneratedFunctions.jl`) — avoiding world-age and per-step eval. `DiscreteProblem(acs,…)` is the natural compile boundary.

Preconditions (from the roadmap): fix the Phase-0 crash bugs (composition of declarative specs must actually work), introduce typed `AttrType`s/validation and orthogonal modalities (Phase 1), remove eval-on-load (Phase 2). Only then is the agentic IR credible.

## AlgebraicAgents.jl synergy

ReactiveDynamics is already most of the way there: its public output `DiscreteProblem(acs::ReactionNetwork; …)` **is** a `SciMLBase.AbstractDEProblem` — exactly what AlgebraicAgents' `DiffEqAgent` accepts. The model is self-contained in `prob.p[:__state__]::ReactiveDynamicsState` (with `:__state0__` for reinit), observables already exist as a first-class concept, and the ensemble `prob_func` already does the deepcopy-restore that `reinit!` needs.

**Recommended route**: a package extension `ext/ReactiveDynamicsAlgebraicAgentsExt.jl` (AlgebraicAgents as `[weakdeps]`/`[extensions]`, no hard dep). Concrete changes: (1) a `to_agent(name, acs; …)` helper wrapping the `DiscreteProblem` as `DiffEqAgent(name, prob, FunctionMap(); observables=observable_map(acs))` — this alone delivers the headline "co-integrate a reaction network with an SDE/ABM in one `simulate(world, T)`"; (2) an **observable bridge** (`getobservable`/`gettimeobservable` dispatching declared obs names to `take(state, key)`; reconcile `Symbol` vs `String` keying); (3) a **state↔agent back-reference** (`agent::Any=nothing` field on `ReactiveDynamicsState`, set at build) so a registered rate can call `getobservable(getagent(state.agent, "../market"), :price)` — the core synergy where an SDE drives pipeline economics; (4) `_reinit!`/`_getparameters`/`_setparameters!` over `state.p` for joint optimization across subsystems.

**Top risks** (verify before committing): (a) **`Params`-wrapping collision** — `DiffEqAgent` wraps `prob.p` in a `mutable struct Params`, but RD's `f` indexes `p` by `Symbol` (`p[:__state__]`, `p[:tstep]`) and `sync_p!` does `merge!(p, state.p)`; if init forwards the `Params` object as `p`, every `p[:__state__]` breaks (mitigate with a delegating `getindex(::Params,::Symbol)`, or use the alternate route below); (b) **clock authority/drift** — the authoritative clock is `state.t` inside `f`, while AA schedules off `integrator.t`; they stay synced only if one `step!` == one `f` call and `dt == tstep` (the dual-clock fragility of #19; the Phase-2 single-clock work is a prerequisite — add a test asserting `integrator.t == state.t` after each step); (c) **statefulness/ensembles** — in-place mutation + deepcopy-reset must wire to `reinit!` (depends on #11 RNG seeding for reproducible composed ensembles); (d) **version/compat** of co-loaded Catlab/DifferentialEquations/SciMLBase. **Alternate route B** if the `Params` snag bites: a bespoke `@aagent`-declared `ReactionNetworkAgent` holding the `ReactiveDynamicsState` directly and implementing `_step!`/`_projected_to`/`getobservable`/`_reinit!` — more code, full control over the clock.

## Refactor roadmap

**Phase 0 — Stabilize** (~1–2 wk, no API changes). Fix the criticals/highs (#1 join, #4 mode, #5 nonblock, #6 observable, #7 capacity, #8 optim warning, #18 sentinels); close the silent-failure class (#9 dropped attrs, error on unknown attrs, throw on malformed reactions, compute ledger col 4); delete phantom exports (#17). **Gate: add the first real unit tests** (parsing values; conservation/capacity after one `evolve!`; `@mode` on a fresh species; a range-less observable; a `:nonblock` reactant over steps; a two-model join asserting merged counts). These tests are the acceptance criterion.

**Phase 1 — Refactor backbone & ontology** (~3–5 wk, macros kept as shims). Replace per-step `eval` with compile-once / `RuntimeGeneratedFunctions.jl` (#3); introduce typed `AttrType`s + a `validate(acs)` pass (#10); re-model modality as orthogonal typed dimensions (#13); promote the reactant relation to ACSet morphisms; define the Ledger ontology precisely + Account/Role (#14, #17); consolidate metadata globals (#27); unify the two eqs parsers (#26); demote configuration macros to functions + extract the dictcall helper + delete dead code (#24).

**Phase 2 — Productionize** (~3–4 wk). Thread an `AbstractRNG` + `seed` (#11); performance (concrete `p`, name→index map, preallocated buffers, no per-sample deepcopy, configurable `n_steps`, collapse the two solver builders) (#12, #22); serialization safety + fidelity (gate `eval`, one typed table for TOML/CSV, symmetric `registered`, round-trip tests) (#2); single-clock solver (drop `(0.0,2.0)`+remake) (#19); partition/escape kwargs (#20); packaging (move doc/notebook/test deps out, `Plots` as weakdep, export the type+builders) (#28); expand the test matrix; fix docs drift (#29).

**Phase 3 — Agentic schemas** (~3–4 wk, builds on 1–2). Ship the typed `ExprNode` IR + `RNSpec` with JSON-Schema export; the non-macro builder API (make `@ReactionNetwork`/`@push` lower to it); the safe whitelisted evaluator + IR↔ACSet stage; an AlgebraicAgents extension (gated on the Phase-2 single-clock work); typed `OptimizationSpec` + non-macro `optimize(acs, spec)` with explicit `:min`/`:max`.

**Sequencing note**: phases are ordered by dependency, not just priority — Phase 0 tests gate Phase 1 (don't refactor an untested broken backbone); the Phase 3 IR depends on the typed `AttrType`s and compile-once stage from Phases 1–2; close the RCE (Phase 2 serialization) before advertising any model-file interchange.
