ADRs 0007–0012 are the Phase-0.5 modeling-language extension increment (2026-06-21), answering the maintainer's business-process modeling asks: a refined/compact/compositional metalanguage with substitutable granularity (0009), a contracted interface with declarative + dumpable initial state (0007), filtration-based selection of agentic-species tokens (0008), an endogenous, state-contingent decision channel — in-model rules/callbacks/conditional transitions — that makes an expressive BD demo possible (0010), full action expressivity — population-level token-field writes plus a general-code escape hatch through the eval-free registry — so callbacks can run arbitrary queries/code without reopening the RCE (0011), and AlgebraicAgents interoperability — a reactive network as a node in the AA hierarchy that exposes its state outbound and reads sibling/parent state inbound via declared wired ports (0012). They map to CONTRACT §10, §11, §9.5, §12, the §12.3/§8.4 amendment, and §13 respectively, and are ALL now IMPLEMENTED (2026-06/07): ADR 0007 declarative `population[]` + `dump_state`/`restore` (`src/interface/checkpoint.jl`, commit `44c9d55`); ADR 0008 `TokenPredicate`/`@select` + `SetField`/`@advance` (`src/predicates.jl`, `src/actions.jl`, `896bc45`); ADR 0009 `refine`/`abstract`/`@compose`/`@pipeline`/`@process` (`src/operators/refine.jl`, `886a610`); ADR 0012 the AA read/coupling surface + `ExternalRef` (`src/interface/aa_coupling.jl`, `src/exprnode.jl`, `d5a367c`) plus the `@agentize` sugar (`ebf7773`/`4f61cfa`). ADRs 0013–0014 are the Phase-0.6 analysis & visualization increment (proposed 2026-06-29, **implemented 2026-06-30**, commit `6174ebe`) — the RESULT-inspection layer answering "inspect an ensemble of runs, gather ledger statistics, extract typical agentic-token trajectories, export, plot, and draw a result-decorated network exec map for (in)efficiency analysis." They sit ON TOP of the §1–§13 modeling layer without disturbing it (read-only over a finished run), map to CONTRACT §14 and §15, and were the FIRST `src/` change of the Phase-0 line — landed as `src/analysis.jl`/`src/export.jl`/`src/visualize.jl` + `ext/RDPlotsExt.jl`/`ext/RDArrowExt.jl`, green under the §14/§15 semantic tests. The engine APIs now SUBSUME the [MVP_BD_DEMO.md](../../demo/bd_acquisition/MVP_BD_DEMO.md) demo's hand-rolled `analysis.jl`/`figures.jl`. 0013's ensemble member-REINIT mode (b) — previously gated on the ADR 0007 §D `_reinit!` completion — has now SHIPPED (`ensemble(...; mode = :reinit)`, the reseed path in `_reinit!` at `src/solvers.jl:964`, commit `1501c78`); the gate is closed. Both ADRs reuse existing infrastructure (the per-program ledger seam, AA's `getobservable`/`run_graphviz`/`wiring_diagram`) rather than adding dependencies. AlgebraicAgents is now the published registry release 0.4 (the earlier `Merck/AlgebraicAgents.jl@main` `[sources]` pin was dropped, commit `eb2ee10`). 0010 and 0011 are maintainer-ratified (2026-06-21) and were driven by the [MVP_BD_DEMO.md](../../demo/bd_acquisition/MVP_BD_DEMO.md) exercise; 0010's repair of the event channel and 0011's reuse of the ADR-0006 §C registry boundary are verified against source. ADR 0015 (post-ACSets naming) landed 2026-07-15 (`bc6cc0a`); old names survive one release as deprecation shims.

Genuinely-deferred items (gates recorded): entity-level refinement — a structured token hosting its own sub-network — is deferred from [ADR 0009](0009-refinement-and-composition.md) §F to a future ADR (design of §A was kept so as not to preclude it). AA `Opera`-level implicit/fixed-point (algebraic-loop) coupling remains future work noted in [ADR 0012](0012-algebraicagents-integration.md) — current coupling is explicit one-tick-lag Jacobi. A threaded ensemble backend (`ensemble(...; parallel=true)` is accepted but runs sequentially) is future work orthogonal to mode (b). Three construction-time modality-validation rules (CONTRACT §1.4) are still `@test_skip` placeholders in `test/semantic/modality_genesis.jl`. The typed `ExprNode` IR + modality re-modeling are specified across [ADR 0003](0003-data-store.md) (store + reactant promotion), [ADR 0005](0005-serialization-json-ir.md) (ExprNode), and [CONTRACT_DRAFT.md](../CONTRACT_DRAFT.md) §1 (modality truth table). A genesis-semantics decision (source vs routing transitions; the `{poisson,scheduled,flow,capacity}` mode tag) is recorded in CONTRACT_DRAFT.md §2/§3 and may be promoted to its own ADR. [ADR 0017](0017-petri-net-vocabulary.md) finishes the ADR 0015 naming debt by retiring `species`/`reactant` — the Catalyst/AlgebraicPetri lineage 0015 deliberately scoped out — for the standard `place`/`marking`/`arc` terms, keeps `token` (canonical Petri vocabulary, glossed in prose against the language-model sense), and stages the JSON key rename as its own step. Because ADRs are append-only, every earlier ADR keeps the old vocabulary; the term dictionary in 0017's appendix is the translation table.
