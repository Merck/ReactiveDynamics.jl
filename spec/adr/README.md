**Vocabulary lineage.** Everything above ADR 0017 was written in the retired CRN vocabulary and keeps it, because ADRs are append-only. Read `species` as **place**, a species count as that place's **marking**, `reactant`/`ReactantSpec` as **arc**/`ArcSpec`, and the `spec*` column symbols as `place*`; the full translation table is the term dictionary in [0017](0017-petri-net-vocabulary.md)'s appendix, mirrored in the CONTRACT's Glossary. ADR 0017 is the boundary: every ADR numbered below it predates the new vocabulary, and every ADR written after it uses it. The same holds one layer down for ADR 0018: in ADRs 0001, 0003, 0004, 0006 and 0007, read the type `Transition` as **`Firing`** (one in-flight execution), `state.transition_recipes` as `state.transitions` (the static table), the old `state.transitions` as `state.sampled_transitions` (that table realized for the current tick), and `ongoing_transitions`/`bound_transition` as `ongoing_firings`/`bound_firing`. 0017's own **Amendments** section (2026-08-24, post-implementation review) carries the two rules that govern any later naming question: `reaction` is retained deliberately because it names the *notation* while Petri vocabulary names the *object model*, and a standard word is adopted when RD's concept is a superset of it, drifted from when it contradicts a commitment, and never reused for a concept at a different layer — which is why the static LHS/RHS entry is an **arc** and the tokens a live firing holds are its **binding**, not an arc. [0018](0018-firing-vs-transition.md) applied the layer rule to the one term 0017 left inverted, and is the last naming item: from 0018 onward a **firing** is one in-flight execution and a **transition** is the static object, at both layers.

ADRs 0007–0012 are the Phase-0.5 modeling-language extension increment (2026-06-21), answering the maintainer's business-process modeling asks: a refined/compact/compositional metalanguage with substitutable granularity (0009), a contracted interface with declarative + dumpable initial state (0007), filtration-based selection of structured (agentic) tokens (0008), an endogenous, state-contingent decision channel — in-model rules/callbacks/conditional transitions — that makes an expressive BD demo possible (0010), full action expressivity — population-level token-field writes plus a general-code escape hatch through the eval-free registry — so callbacks can run arbitrary queries/code without reopening the RCE (0011), and AlgebraicAgents interoperability — a reactive network as a node in the AA hierarchy that exposes its state outbound and reads sibling/parent state inbound via declared wired ports (0012). They map to CONTRACT §10, §11, §9.5, §12, the §12.3/§8.4 amendment, and §13 respectively, and are ALL now IMPLEMENTED (2026-06/07): ADR 0007 declarative `population[]` + `dump_state`/`restore` (`src/interface/checkpoint.jl`, commit `44c9d55`); ADR 0008 `TokenPredicate`/`@select` + `SetField`/`@advance` (`src/predicates.jl`, `src/actions.jl`, `896bc45`); ADR 0009 `refine`/`abstract`/`@compose`/`@pipeline`/`@process` (`src/operators/refine.jl`, `886a610`); ADR 0012 the AA read/coupling surface + `ExternalRef` (`src/interface/aa_coupling.jl`, `src/exprnode.jl`, `d5a367c`) plus the `@agentize` sugar (`ebf7773`/`4f61cfa`).
