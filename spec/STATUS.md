## Where the durable spec lives

ADRs record context/decision/consequences/rejected-options; the CONTRACT records the resulting semantics.
- **[PR_DRAFT.md](PR_DRAFT.md)** — the draft PR narrative for the rework (the headline changes, tiered against the ADRs).
- **[DOCS_CHARTER.md](DOCS_CHARTER.md)** — the tracking charter for the documentation/tutorials rework (the standalone PR into `rework`, branch `docs-tutorials`): the Diátaxis structure, the demo→docs migrate-in-place mapping, the tiered-tutorial + case-study scope, and the per-facet progress tracker. The docs counterpart to this file.
- **[AGENT_WORKFLOW_CHARTER.md](AGENT_WORKFLOW_CHARTER.md)** — the tracking charter for the *agent-facing* surface (drafted 2026-09-22): a portable skill/plugin layer carrying a user from a business question through a decision frame, a validate-clean `model.rdj.json`, a dynamic plausibility gate, and a reproducible `(model, seed)` briefing. Non-normative; the CONTRACT and ADRs remain the source of truth.

- **[../readme.md](../readme.md)** — the user-facing package README (about + demos).
- **[../CLAUDE.md](../CLAUDE.md)** — the agent-facing guide (what the project is, current post-ADR-0015 architecture, build/test commands, dev-loop gotchas).

## Recently closed

- **Construction-time modality validation (CONTRACT §1.4) — DONE (`53d1fac`).** `validate_modalities` in `src/solvers.jl` runs in the `ReactionNetworkProblem` constructor (before any closure compiles or tick runs) and rejects the three illegal §1.4 configs with a clear `ArgumentError`: `{:nonblock, :conserved}`; `:rate` (perstep) with a concrete `cycletime == 0`; `:rate` on a structured place. It reuses the eval-free static arc decomposition and mirrors the runtime modality union; Expr/param-valued cycletimes and `@choose`/bidirectional lines are left to run (not statically decidable / the documented escape hatch). The three former `@test_skip` acceptance placeholders in `test/semantic/modality_genesis.jl` are now live passing `@test_throws`, and two collateral test models that had built the now-forbidden `@rate`+ct=0 foot-gun were legalized. Suite is green with no remaining `@test_skip` PLACEHOLDERS (the three surviving `@test_skip`s are environment guards — see Conventions).

- **Firing-vs-transition rename (ADR 0018) — DONE.** Accepted as Option C and landed with ADR 0017, so authors absorb one migration rather than two. The inversion is gone: a `Firing` is one in-flight execution, `state.transitions` is the static table. Two things the ADR's first draft got wrong and the implementation corrected: `transitions` was NOT a free name (it held the per-tick evaluated snapshot, now `sampled_transitions` — collapsing the two is a load-time `duplicate field name` error, which is how it was caught), and the blast radius was ~250 text sites, not 92. The four open questions are resolved inline in the ADR's **Resolutions** section; nothing is gated. Out of scope by design and still true: the `:T` object and its `trans*` columns (`src/operators/joins.jl` selects that family by the literal substring `"trans"`), the serialized keys (already `"transitions"`), and AA agent paths (built from `:transName`).

## Remaining work — ENGINE (all deferred; each with its gate — nothing non-deferred is open)

1. **`dump_state` in-flight limitation (implemented WITH a documented constraint, not a gap).** ADR 0007 §C `dump_state`/`restore` shipped, but `dump_state` REFUSES to dump when any transition is mid-cycle — it errors unless `ongoing_firings` is empty (`src/interface/checkpoint.jl:51-54`), i.e. dump is a clean-tick-boundary operation only (Milestone-1 scope). Serializing in-flight `ongoing` instances eval-free is the open ADR 0007 §C question; not a bug, an accurately-scoped limitation.
2. **Live-mutation GROWTH API + `apply_patch` (ADR 0004) — specified, NOT implemented; deferred.** The contract names an append-only live-mutation API as the *only* sanctioned way to change a running model (§6.2, §7.5 J8, §8.6 S6, §10.1's Live row), but `add_place!`, `add_transition!`, `add_param!`, `refresh_wrap_fun!`, `apply_patch` and the `spec_delta` JSON patch document have ZERO definitions in `src/`. The SPLIT is what to remember: the soft-deactivate half IS implemented (`activate!`/`deactivate!`, `src/actions.jl:167,178`, plus the `Activate`/`Deactivate` actions, with in-flight instances running to completion per INV-3), and `add_structured_token!` (`src/interface/agents.jl:62`) grows the AA `inners` dict — but nothing can append a row to a live model's positional columns, so the §8.6 acquisition lever has no on-disk patch form and mid-run change means rebuilding from scratch, losing the RNG stream and the in-flight instances append-only mutation exists to preserve. `@add_place` (`src/interface/update.jl:246`) is NOT this API — it is authoring-time, which §7.5 J8 forbids once live. Nothing is currently blocked and the suite is green because nothing tests these symbols. **Gate:** implement when a demo actually exercises mid-run injection, so ADR 0004's INV-1…INV-4 (and the delicate parts — the `refresh_wrap_fun!` varmap re-derivation and the `sol` widening policy) are tested against a use rather than in the abstract. The CONTRACT passages carry a specified-not-implemented spec note; tracked as [issue #27](https://github.com/Merck/ReactiveDynamics.jl/issues/27).
3. **Entity-level refinement (ADR 0009 §F) — deferred.** A structured token hosting its own sub-network. `refine`/`abstract`/`@compose`/`@pipeline`/`@process` (transition-level refinement + composition) all shipped; only the entity-hosts-a-subnetwork axis is deferred to a future ADR. §A of ADR 0009 was designed so as not to preclude it.
4. **Threaded ensemble backend — deferred.** `ensemble(...; parallel = true)` is accepted but currently runs sequentially (`src/analysis.jl:300`, kwarg at `:307`); a real threaded backend is future work, orthogonal to mode (b) (members are independent, so it is a safe extension).
5. **AA `Opera`-level implicit/fixed-point (algebraic-loop) coupling — deferred.** Current AA coupling is explicit one-tick-lag Jacobi (`src/interface/aa_coupling.jl:123`); a within-tick fixed point is a separate AA-level `Opera` design (noted in ADR 0012).
6. **ADR 0003 Phase 3 (`to_acset` weakdep interop view) — REJECTED / will-not-do (2026-07-15).** No AlgebraicJulia/ACSets/Catlab interop view will be built; interop is off the BD/rNPV roadmap and impossible for the running stateful engine. This is a definitive rejection, not a parked/deferred option — any future interop would be a new ADR against the then-current engine (the dependency-free typed IR is the permanent core). Recorded in ADR 0003 Resolved. NOT counted as remaining work.
7. **Follow-up naming pass (`dt`/`tstep`) — DONE 2026-07-16.** CONTRACT_DRAFT flagged `tstep` as an internal alias / rename candidate; explicitly out of scope for ADR 0015, folded into this separate pass. Landed: the internal keyword-bag key and the accepted keyword now both use `dt` (matching the `state.dt` field, reconciled by name not position); the legacy `tstep` meta keyword is an accepted-but-deprecated alias mapped to `dt` with a depwarn for one release. Also fixed a latent silent-ignore bug (a user-supplied `tstep` was previously overwritten before use).
8. **Tutorial/documentation rework — IN PROGRESS on branch `docs-tutorials` (standalone PR into `rework`).** Chartered and tracked in **[DOCS_CHARTER.md](DOCS_CHARTER.md)**: tiered onboarding tutorials (introductory/advanced/expert) + technical deep-dives (serialization, composition), three applied decision case studies (marginal-scientist flagship, in-licensing BD/M&A, kill-a-program), a rebuilt capability-organized API reference (the current `docs/src/index.md` references removed macros), and — for the "why" — links to the normative contract/ADRs plus two companion papers (a methodology paper and an HBR-style adoption/value paper; the on-site explanation quadrant D1/D2 was dropped 2026-07-21) — all literate, on a Documenter+Literate site, with the seven `demo/` tours migrated in place as the single source of truth. First increment landed: the charter + a fully-rendered introductory-tutorial exemplar (`docs/literate/tutorials/introductory.jl`) + the Documenter+Literate build scaffold (`docs/make.jl`, `docs/Project.toml`, `docs/build_literate.jl`). Remaining facets tracked in the charter's §10.

## Build / test / dev

```bash
julia --project=. -e 'using Pkg; Pkg.instantiate()'   # install deps
julia --project=. -e 'using Pkg; Pkg.test()'          # run the semantic suite
julia --project=. -e 'using ReactiveDynamics'         # load the package
```

Tests live in `test/semantic/*.jl` (entry `test/runtests.jl` → `test/semantic/runtests.jl`), with their own `test/Project.toml` that declares the test-only deps (`Plots`, `Arrow`, `DataFrames`, `Distributions`, …) that the main project keeps as weakdeps. Formatting is [Runic](https://github.com/fredrikekre/Runic.jl) (`julia -m Runic --inplace src test ext docs/make.jl demo`; `--check .` to verify) — opinionated and non-configurable, so there is no formatter config file; the bulk reformat commit is in `.git-blame-ignore-revs`. NB adding a NEW `src/` file requires clearing the compiled cache (Revise won't pick it up otherwise); there is no `dev/` directory on this branch, so the Revise-based test server earlier revisions of this file described is not available here. Environment-dependent features skip rather than fail when their backend is missing, and exactly THREE `@test_skip` environment guards exist in the suite — `visualization.jl:132` (a Graphviz backend), `visualization.jl:203` (Plots not loaded) and `analysis_observability.jl:333` (Arrow not loaded). They are guards, not gaps. Only the Graphviz one trips on CI: Plots and Arrow are declared in `test/Project.toml` and so are always present, whereas Graphviz is a system binary the runners do not install — which is exactly the 835-vs-834 difference in the tally above.
